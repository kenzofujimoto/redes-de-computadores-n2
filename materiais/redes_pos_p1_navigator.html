ICMP — Internet Control Message Protocol

Protocolo auxiliar do IP usado para relatar erros e diagnósticos. Não transporta dados de usuário.

Mensagens principais

TipoUsoComando

O ping usa ICMP tipo 8 (request) e tipo 0 (reply). O TTL decrementado a zero gera tipo 11 (Time Exceeded).

DHCP — Dynamic Host Configuration Protocol

Atribui endereços IP automaticamente a clientes. Funciona sobre UDP (porta 67 servidor / 68 cliente).

Processo DORA

Cliente Servidor DHCP | | |--- Discover ------>| (broadcast: "tem alguém aí?") |<---- Offer --------| (oferta de IP) |--- Request ------->| (aceito esse IP!) |<--- Acknowledge ---| (confirmado, use por X tempo)

Parâmetros fornecidos

  • Endereço IP e máscara de sub-rede
  • Gateway padrão
  • Servidor DNS
  • Tempo de concessão (lease time)

DHCP usa broadcast no Discover e Request — por isso não passa por roteadores naturalmente. É necessário um DHCP Relay Agent para redes segmentadas.

NAT — Network Address Translation

Traduz endereços IP privados para públicos (e vice-versa) na borda da rede. Conserva o espaço de IPs públicos.

TipoDescrição
NAT Estático1 IP privado → 1 IP público (fixo)
NAT DinâmicoPool de IPs privados → pool de IPs públicos
PAT / NAT OverloadMuitos IPs privados → 1 IP público (usando portas)
Rede interna Roteador NAT Internet 192.168.1.10:4523 → 200.100.50.1:4523 → 8.8.8.8 192.168.1.11:8080 → 200.100.50.1:8080 → 1.1.1.1

PAT (Port Address Translation) é o mais comum em residências: todos os dispositivos compartilham 1 IP público, diferenciados pela porta.

IPv6 — Internet Protocol versão 6

Substituto do IPv4. Endereços de 128 bits (16 bytes), notação hexadecimal separada por :.

Formato

2001:0db8:85a3:0000:0000:8a2e:0370:7334 ↓ simplificado (omitir zeros à esquerda) 2001:db8:85a3:0:0:8a2e:370:7334 ↓ comprimir grupos de zeros consecutivos com :: 2001:db8:85a3::8a2e:370:7334

Tipos de endereço IPv6

IPv6 não usa broadcast. Usa multicast e anycast. O NAT geralmente não é necessário em IPv6 (espaço de endereços suficiente).

Camada de Enlace

Protocolos de Acesso Múltiplo ao Canal

Quando múltiplos dispositivos compartilham o mesmo meio físico, é necessário controlar quem transmite.

CategoriaProtocoloComo funciona
ParticionamentoTDMA, FDMADivide tempo ou frequência
Acesso aleatórioCSMA/CD, CSMA/CADetecta/evita colisão
RevezamentoToken Ring, PollingPassa o "direito" de transmitir

CSMA/CD (Ethernet com fio)

  • Carrier Sense: escuta o meio antes de transmitir
  • Multiple Access: múltiplos dispositivos no mesmo meio
  • Collision Detection: detecta colisão e para, espera tempo aleatório (backoff exponencial)

CSMA/CA (Wi-Fi)

  • Collision Avoidance: não detecta, evita colisões (no ar é difícil detectar)
  • Usa RTS/CTS opcionalmente para reservar o meio

Protocolo Ethernet

Padrão dominante em redes cabeadas (IEEE 802.3). Opera na camada de enlace.

Frame Ethernet

| Preâmbulo | MAC Dest | MAC Orig | Tipo/Tam | Dados | FCS | | 8 bytes | 6 bytes | 6 bytes | 2 bytes | 46-1500| 4 bytes|

Endereço MAC

  • 48 bits (6 bytes), notação hexadecimal: AA:BB:CC:DD:EE:FF
  • Primeiros 3 bytes: OUI (fabricante) | Últimos 3 bytes: serial
  • Endereço de broadcast: FF:FF:FF:FF:FF:FF
  • Gravado na NIC (pode ser alterado por software)

MAC é usado na camada 2 (dentro da mesma rede). IP é usado na camada 3 (entre redes). O ARP faz a ponte entre os dois.

Camada de Enlace

ARP — Address Resolution Protocol

Descobre o endereço MAC associado a um endereço IP conhecido na mesma rede local.

Situação: A (192.168.1.10) quer falar com B (192.168.1.20) A não sabe o MAC de B. A → Broadcast: "Quem tem o IP 192.168.1.20? Me diga seu MAC!" B → Unicast p/ A: "Sou eu! Meu MAC é AA:BB:CC:11:22:33" A armazena o par (IP → MAC) em seu cache ARP.

Comandos úteis

  • arp -a — exibe a tabela ARP no Windows/Linux
  • arp -d — limpa o cache ARP

ARP Spoofing: atacante responde falsamente ao ARP para interceptar tráfego (ataque man-in-the-middle). Importante em Segurança!

VLSM — Variable Length Subnet Mask

Permite usar máscaras de tamanho variável para otimizar o uso de IPs. Fundamental para o exame!

Estratégia VLSM

  • Ordene as sub-redes da maior para a menor (número de hosts)
  • Aloque a maior primeiro, depois a próxima rede disponível
  • Escolha o menor prefixo que acomoda os hosts necessários

Exemplo prático

Rede base: 10.0.0.0/24 Requisitos: RH(50 hosts), TI(25 hosts), Gerência(10 hosts), Link(2 hosts) RH (50 hosts) → /26 (62 hosts úteis) → 10.0.0.0/26 Faixa: 10.0.0.1 – 10.0.0.62 (BC: 10.0.0.63) TI (25 hosts) → /27 (30 hosts úteis) → 10.0.0.64/27 Faixa: 10.0.0.65 – 10.0.0.94 (BC: 10.0.0.95) Gerência (10h) → /28 (14 hosts úteis) → 10.0.0.96/28 Faixa: 10.0.0.97 – 10.0.0.110 (BC: 10.0.0.111) Link (2 hosts) → /30 (2 hosts úteis) → 10.0.0.112/30 Faixa: 10.0.0.113 – 10.0.0.114 (BC: 10.0.0.115)

SNMP — Simple Network Management Protocol

Protocolo padrão para gerenciamento de dispositivos em redes IP. Usa UDP porta 161 (agente) e 162 (trap).

Componentes

  • NMS (Network Management Station): o "gerente" — consulta e controla
  • Agente: software no dispositivo gerenciado (roteador, switch, servidor)
  • MIB (Management Information Base): banco de dados de variáveis gerenciadas

Operações SNMP

OperaçãoQuem iniciaO que faz
GETNMS → AgenteLê um valor da MIB
SETNMS → AgenteAltera um valor na MIB
TRAPAgente → NMSNotifica evento (não solicitado)
GETBULKNMS → AgenteLê múltiplos valores (SNMPv2+)

SNMPv3 adicionou autenticação e criptografia. Versões anteriores (v1, v2c) usam apenas "community strings" (senhas em texto plano — inseguro).

Arquitetura de Redes sem Fio

ModoDescrição
Infraestrutura (BSS)Clientes se conectam via AP (Access Point) — mais comum
Ad hoc (IBSS)Dispositivos se conectam diretamente entre si
ESSMúltiplos APs com o mesmo SSID — roaming

Componentes

  • AP (Access Point): ponto de acesso sem fio
  • SSID: nome da rede Wi-Fi
  • BSS: Basic Service Set — uma célula (1 AP + seus clientes)
  • ESS: Extended Service Set — vários APs conectados ao mesmo DS
  • DS: Distribution System — infraestrutura com fio conectando os APs
