Tutorial de roteamento estático no Packet Tracer com topologia interativa

Cenário

Topologia usada em todo o tutorial

Três roteadores conectados em série. Cada roteador tem uma LAN local e interfaces WAN entre si. O objetivo é fazer o PC1 pingar o PC3 passando pelos três roteadores.

RT1Passo a passo

Configurando as interfaces e rotas estáticas do RT1

Passo 1 — entrar no modo de configuração

No Packet Tracer, clique no roteador RT1 → aba CLI. Você verá o prompt Router>.

Router> enable Router# configure terminal Router(config)# hostname RT1 RT1(config)#

Modo enable = modo privilegiado (acesso total). Modo configure terminal = onde você faz todas as configurações.

Passo 2 — configurar a interface LAN (Gig0/0)

Esta interface conecta o RT1 à rede local 192.168.1.0/24.

RT1(config)# interface GigabitEthernet0/0 RT1(config-if)# ip address 192.168.1.1 255.255.255.0 RT1(config-if)# no shutdown RT1(config-if)# %LINK-5-CHANGED: Interface GigabitEthernet0/0, changed state to up RT1(config-if)# exit

no shutdown é obrigatório — interfaces Cisco vêm desligadas por padrão. Sem esse comando a interface fica "down" mesmo com cabo conectado.

Passo 3 — configurar a interface WAN (Gig0/1)

Esta interface conecta o RT1 ao RT2 pelo link 10.0.12.0/30.

RT1(config)# interface GigabitEthernet0/1 RT1(config-if)# ip address 10.0.12.1 255.255.255.252 RT1(config-if)# no shutdown RT1(config-if)# exit

255.255.255.252 é a máscara do /30. Ela dá apenas 2 hosts úteis — ideal para links ponto-a-ponto entre roteadores.

Passo 4 — adicionar as rotas estáticas

RT1 precisa saber como chegar nas redes que ele não conhece diretamente: LAN 2 (192.168.2.0) e LAN 3 (192.168.3.0).

RT1(config)# ip route 192.168.2.0 255.255.255.0 10.0.12.2 RT1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2

Sintaxe: ip route [rede-destino] [máscara] [próximo-salto]. O próximo salto de RT1 para qualquer destino além de RT2 é sempre 10.0.12.2 (a outra ponta do link).

Passo 5 — salvar a configuração

RT1(config)# end RT1# write memory Building configuration... [OK]

Sem write memory (ou copy run start), a configuração é perdida quando o Packet Tracer fecha o arquivo. Sempre salve!

RT2Roteador central

RT2 — o mais trabalhoso: 3 interfaces e 2 rotas

Passo 1 — entrar e nomear

Router> enable Router# configure terminal Router(config)# hostname RT2

Passo 2 — interface LAN (Gig0/0)

RT2(config)# interface GigabitEthernet0/0 RT2(config-if)# ip address 192.168.2.1 255.255.255.0 RT2(config-if)# no shutdown RT2(config-if)# exit

Passo 3 — interface WAN para RT1 (Gig0/1)

RT2(config)# interface GigabitEthernet0/1 RT2(config-if)# ip address 10.0.12.2 255.255.255.252 RT2(config-if)# no shutdown RT2(config-if)# exit

Passo 4 — interface WAN para RT3 (Gig0/2)

RT2(config)# interface GigabitEthernet0/2 RT2(config-if)# ip address 10.0.23.1 255.255.255.252 RT2(config-if)# no shutdown RT2(config-if)# exit

Passo 5 — rotas estáticas

RT2 precisa de rotas para LAN 1 (via RT1) e LAN 3 (via RT3).

RT2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1 RT2(config)# ip route 192.168.3.0 255.255.255.0 10.0.23.2

Para LAN 1 o next-hop é 10.0.12.1 (RT1). Para LAN 3 é 10.0.23.2 (RT3). Direções diferentes para destinos diferentes.

Passo 6 — salvar

RT2(config)# end RT2# write memory [OK]
RT3

RT3 — simétrico ao RT1

Passo 1 — nomear e entrar

Router> enable Router# configure terminal Router(config)# hostname RT3

Passo 2 — interface LAN (Gig0/0)

RT3(config)# interface GigabitEthernet0/0 RT3(config-if)# ip address 192.168.3.1 255.255.255.0 RT3(config-if)# no shutdown RT3(config-if)# exit

Passo 3 — interface WAN (Gig0/1)

RT3(config)# interface GigabitEthernet0/1 RT3(config-if)# ip address 10.0.23.2 255.255.255.252 RT3(config-if)# no shutdown RT3(config-if)# exit

Passo 4 — rotas estáticas

RT3 precisa chegar em LAN 1 e LAN 2, ambas via RT2 (10.0.23.1).

RT3(config)# ip route 192.168.1.0 255.255.255.0 10.0.23.1 RT3(config)# ip route 192.168.2.0 255.255.255.0 10.0.23.1

O único vizinho de RT3 é RT2, então o next-hop de todas as rotas externas é sempre 10.0.23.1.

Passo 5 — salvar

RT3(config)# end RT3# write memory [OK]
Verificação

Comandos para verificar se tudo funcionou

1. Ver a tabela de roteamento

RT1# show ip route Codes: C - connected, S - static, R - RIP, ... 10.0.0.0/30 is subnetted, 1 subnets C 10.0.12.0/30 is directly connected, GigabitEthernet0/1 192.168.1.0/24 is variably subnetted, 2 subnets, 2 masks C 192.168.1.0/24 is directly connected, GigabitEthernet0/0 S 192.168.2.0/24 [1/0] via 10.0.12.2 S 192.168.3.0/24 [1/0] via 10.0.12.2

C = rede conectada diretamente (interface configurada). S = rota estática que você configurou. Se aparecer S, funcionou!

2. Testar ping entre redes

RT1# ping 192.168.3.10 Type escape sequence to abort. Sending 5, 100-byte ICMP Echos to 192.168.3.10, timeout is 2 seconds: !!!!! Success rate is 100 percent (5/5), round-trip min/avg/max = 0/1/3 ms

!!!!! = 5 pings com sucesso. Se aparecer ..... (pontos) a rota não está funcionando.

3. Testar traceroute

RT1# traceroute 192.168.3.10 Type escape sequence to abort. Tracing the route to 192.168.3.10 1 10.0.12.2 1 msec (RT2) 2 10.0.23.2 1 msec (RT3) 3 192.168.3.10 1 msec

O traceroute mostra cada salto. Você consegue ver exatamente por onde o pacote passou: RT1 → RT2 → RT3 → PC3.

Rota padrãoAvançado

Rota padrão (default route) — 0.0.0.0/0

A rota padrão captura qualquer destino que não tenha rota específica na tabela. É usada para conectar a rede à Internet.

RT1(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.2 RT1(config)# end RT1# show ip route S* 0.0.0.0/0 [1/0] via 10.0.12.2 (rota padrão — asterisco = candidata a default)

S* indica rota estática padrão (S = static, * = default). O /0 significa "zero bits de rede" — ou seja, qualquer endereço casa com essa rota.

Quando usar rota padrão vs rota específica

CenárioUse
Roteador de borda (acessa a Internet)Rota padrão + rotas internas específicas
Roteador de extremidade (stub router)Apenas rota padrão apontando para o núcleo
Roteador do núcleo (conhece toda a topologia)Somente rotas específicas

Propagar a rota padrão com um protocolo dinâmico

RT1(config)# router ospf 1 RT1(config-router)# default-information originate

Isso distribui a rota padrão automaticamente para todos os outros roteadores OSPF. Mas isso já é protocolo dinâmico — fora do escopo do roteamento estático puro.

Princípio fundamental: roteamento é bidirecional. Se RT1 tem rota para LAN 3, RT3 precisa ter rota de volta para LAN 1. Sem a rota de retorno o ping vai mas não volta — o host recebe o pacote mas não consegue responder.
