Tutorial interativo de cálculo IPv4 e VLSM passo a passo

Método geral

Como resolver qualquer exercício de IPv4 — os 3 conceitos que você precisa

1

Entenda o que o prefixo diz

O número após a barra (/28) indica quantos bits são da rede. Os bits restantes (32 − prefixo) são de host.

Bits de host = 32 − prefixo /28 → 32 − 28 = 4 bits de host /26 → 32 − 26 = 6 bits de host /24 → 32 − 24 = 8 bits de host
2

Calcule o tamanho do bloco

O bloco é o "salto" entre redes consecutivas. É sempre uma potência de 2.

Bloco = 2^(bits de host) /28 → 2^4 = 16 /26 → 2^6 = 64 /24 → 2^8 = 256
3

Encontre a rede do IP

Divida o octeto relevante pelo bloco, pegue só a parte inteira e multiplique de volta.

Rede = floor(octeto ÷ bloco) × bloco Ex: IP = 209.98.85.145 /28 → bloco = 16 145 ÷ 16 = 9,0625 → floor = 9 Rede = 9 × 16 = 144 → 209.98.85.144
Exemplo 1189.251.75.89/26

Resolvendo passo a passo — prefixo no 4º octeto

Passo 1 — ler o prefixo

Endereço: 189.251.75.89 / 26 Prefixo: 26 bits de rede Bits host: 32 − 26 = 6 bits

Azul = bits de rede (26) · Laranja = bits de host (6)

Passo 2 — calcular o bloco

Bloco = 2^6 = 64 Redes /26 no 4º octeto (0 a 255): 0 → 0–63 64 → 64–127 128 → 128–191 192 → 192–255

O bloco 64 significa que as redes começam em 0, 64, 128, 192... São 4 sub-redes de /26 dentro de um /24.

IP: 189.251.75.89 Bloco: 64 89 ÷ 64 = 1,390... → floor = 1 Rede = 1 × 64 = 64 Endereço de rede: 189.251.75.64

Exemplo 2200.98.178.100/19

Prefixo que "corta" no 3º octeto — como lidar?

Passo 1 — identificar o octeto relevante

Prefixo /19: 8 bits → 1º octeto (rede fixa) 8 bits → 2º octeto (rede fixa) 3 bits → 3º octeto (parcialmente rede) ───────────────────────────────────── Total rede: 19 bits Bits de host restantes: 32 − 19 = 13 bits 5 bits no 3º octeto (parte de host) 8 bits no 4º octeto (inteiro de host)

Quando o prefixo está entre 8 e 16, o 3º octeto é dividido. Quando está entre 16 e 24, o 4º octeto é dividido. Quando está entre 0 e 8, o 2º octeto é dividido.

Passo 2 — calcular o bloco no 3º octeto

O /19 usa 3 bits do 3º octeto para rede, sobrando 5 bits para host neste octeto. Bloco no 3º octeto = 2^5 = 32 Redes /19 no 3º octeto: 0 → 0–31 32 → 32–63 64 → 64–95 96 → 96–127 128 → 128–159 160 → 160–191 ← nosso IP (178) cai aqui 192 → 192–223 224 → 224–255

Passo 3 — encontrar a rede

IP: 200.98.178.100 Bloco no 3º octeto: 32 178 ÷ 32 = 5,5625 → floor = 5 Rede no 3º octeto = 5 × 32 = 160 Endereço de rede: 200.98.160.0

Quando a rede atravessa octetos, o primeiro host válido começa em .0.1 do octeto da rede, e o broadcast termina em .X.255 do último octeto do bloco.

Passo 4 — preencher todos os campos

Endereço de rede: 200.98.160.0 1º IP válido: 200.98.160.1 Último IP válido: 200.98.191.254 Broadcast: 200.98.191.255 Próxima rede: 200.98.192.0/19 Lógica do broadcast: 3º octeto: 160 + 32 − 1 = 191 4º octeto: sempre 255 quando o 4º é inteiro de host

Hosts úteis

2^13 − 2 = 8190

Máscara

255.255.224.0

O método VLSM

A lógica por trás do VLSM

1

Ordene as redes da maior para a menor

Sempre aloque o maior bloco primeiro. Se começar pelo menor, pode não sobrar espaço contíguo para os grandes.

2

Escolha o menor prefixo que acomoda os hosts

Hosts úteis = 2^n − 2. Escolha o menor n onde isso é ≥ quantidade pedida. Prefixo = 32 − n.

3

A próxima rede começa no broadcast + 1

Depois de calcular o broadcast da rede atual, some 1 para obter o início da próxima. Sem pular, sem desperdiçar.

4

Gateway = último IP válido (por padrão do professor)

O gateway de cada VLAN é o último endereço antes do broadcast: broadcast − 1.

Exemplo VLSM10.0.0.0/8

VLANs: A=1000, B=200, C=50, D=10, E=2

Este é o exercício gabaritado do professor. Acompanhe o raciocínio.

Sempre escolha o n mínimo. Ex: 1000 hosts — n=10 dá 1022, que é suficiente. n=9 daria 510, insuficiente.

Passo 2 — VLAN A (1000 hosts → /22)

Rede base: 10.0.0.0 Prefixo /22 → bloco no 3º octeto = 2^(24−22) = 2^2 = 4 Rede: 10.0.0.0 Broadcast: 10.0.3.255 (0 + 4 − 1 = 3 no 3º octeto) 1º válido: 10.0.0.1 Último válido: 10.0.3.254 Gateway: 10.0.3.254 Próxima rede: 10.0.4.0 (broadcast + 1 no 3º octeto)

Passo 3 — VLAN B (200 hosts → /24)

Começa onde a VLAN A terminou: 10.0.4.0 Prefixo /24 → bloco inteiro no 3º octeto = 256 Rede: 10.0.4.0 Broadcast: 10.0.4.255 1º válido: 10.0.4.1 Último válido: 10.0.4.254 Gateway: 10.0.4.254 Próxima rede: 10.0.5.0

Passo 4 — VLAN C (50 hosts → /26)

Começa em: 10.0.5.0 Prefixo /26 → bloco no 4º octeto = 2^6 = 64 Rede: 10.0.5.0 Broadcast: 10.0.5.63 (0 + 64 − 1) 1º válido: 10.0.5.1 Último válido: 10.0.5.62 Gateway: 10.0.5.62 Próxima rede: 10.0.5.64

Passo 5 — VLAN D (10 hosts → /28)

Começa em: 10.0.5.64 Prefixo /28 → bloco no 4º octeto = 2^4 = 16 Rede: 10.0.5.64 Broadcast: 10.0.5.79 (64 + 16 − 1) 1º válido: 10.0.5.65 Último válido: 10.0.5.78 Gateway: 10.0.5.78 Próxima rede: 10.0.5.80

Passo 6 — VLAN E (2 hosts → /30)

Começa em: 10.0.5.80 Prefixo /30 → bloco no 4º octeto = 2^2 = 4 Rede: 10.0.5.80 Broadcast: 10.0.5.83 (80 + 4 − 1) 1º válido: 10.0.5.81 Último válido: 10.0.5.82 Gateway: 10.0.5.82 Próxima rede: 10.0.5.84

/30 é o menor prefixo útil: 2 hosts. Usado em links ponto-a-ponto (ex: entre dois roteadores).

Dica crítica

Quando o VLSM atravessa octetos

Ex: VLAN A usa /22 começando em 10.0.0.0 Bloco /22 no 3º octeto = 4 Broadcast do /22: 3º octeto = 0 + 4 − 1 = 3, 4º = 255 → 10.0.3.255 Próxima rede: 3º octeto + 1 = 4, 4º = 0 → 10.0.4.0

Quando o bloco termina no 3º octeto, o 4º octeto do broadcast é sempre 255, e o 4º octeto da próxima rede é sempre 0.
